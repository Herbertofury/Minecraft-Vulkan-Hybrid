# Grass ordering and invalidation compatibility

Only the original private `Grassier-Grass-1.4.5-Render-Performance-Fix-REPLACEMENT-2.jar`, SHA256 `91006e8220e65572d7e9e1e54b6058526c4adf908faedc750c9f19f13623df8c`, is supported. A whole-JAR digest and exact injection counts fail closed. Original grass code/assets are not redistributed; this addon is new GPL-3.0-only code with Minecraft 1.20.1 pack format 15.

Version 1.0.0 evaluates each original pure distance once and performs a stable primitive-key sort. Its six native trials improved median FPS by 7.60% but worsened lows/tails, so it was not promoted. Version 1.0.1 memoizes only an identical section prefix, count and all three raw camera doubles independently for each sort site. Changed input/camera or failure invalidates reuse. Owner-local arrays are bounded to 65,536 entries; larger sorts use temporary scratch. Mesh/world/shader/frustum/animation state is never memoized. Independent JDK stable-order checks and three unsafe controls pass.

The 1.0.1 six-run native ABBAAB medians were 1,202.96 to 1,611.06 FPS (+33.92%), 1% low 410.26 to 454.47 FPS, p99 2.2736 to 2.0179 ms. Original grass remains visible and six native reload/animation/trail/dimension checks pass within their stated scope. This remains below target; a 10.45 ms interval rules out zero-hitch acceptance. Other workloads and light repository work overlapped parts of the comparison. See [all captures and limits](../../benchmarks/results/cumulative-foundation-20261005/REPORT.md).

Development 1.0.3 filters geometry/light invalidations only on the render owner while the original concurrent producer queues drain. Cached snapshots, including empty meshes, and first/replacement builds in flight always retain invalidations. A never-cached, non-flight section has no old snapshot: its retained first-build candidate reads current geometry/light when it becomes visible/loaded. Unexpected callers or destination sets keep original behavior without reading owner-confined containers. Neither event producer, build budget, range, density, assets, animation, LOD nor cached-section rebuild logic changes. The lifecycle model covers before-first-scan, hidden/unloaded sections, mutations during async capture, light updates, movement, eviction and reload; dropping cached or in-flight changes fails the negative controls. The six-run 1.0.1/1.0.3 native comparison measured 1,639.43 to 1,845.64 FPS (+12.58%), 1% low 469.15 to 473.96 and p99 2.0271 to 1.9179 ms. Original grass and all other JARs remained fixed. This incremental result concerns the original .9 renderer. Hari .10 then reached 2,617.09 median FPS in a separate sole-renderer study; percentages from different series are not combined. Current .11 plus this addon passes seven bounded native grass checks and three captures above 2,432 FPS. Complete shader/style/pack and zero-hitch acceptance remain pending.

The preliminary 1.0.2 probe had a stale embedded version string and is retained as a diagnostic only; 1.0.3 corrects metadata and is the tested build. Build with Java 17: `source/gradlew -p compat/grass-distance-sort build`. Output: `build/libs/mvh-grass-distance-compat-1.0.3.jar`. Earlier source/JAR versions stay preserved. Shader-provider, all-style and full-pack acceptance remain unfinished.
