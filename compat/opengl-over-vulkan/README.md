# OpenGL over Vulkan development bridge

The requested compatibility behavior is to execute mod OpenGL rendering through Vulkan while keeping the mod renderer's features. Hari's current native translation contract is partial and deliberately selects OpenGL when Embeddium, Oculus or Indigo own the render pipeline. Bypassing that gate would not supply their missing translations.

This development bridge uses upstream **Mesa Zink 26.2.4**, which translates OpenGL into Vulkan, beneath the existing OpenGL mods. It retains Embeddium, Oculus, shader/resource packs and other renderer features instead of installing another competing terrain renderer. Hari's native renderer selector remains conservative; `OPENGL_FALLBACK` in its log describes Minecraft's API, not proof of which driver executes that API. The native GL vendor/renderer/version and Vulkan driver must independently establish Zink on the actual RTX 4090. No software backend or spoofed version is acceptable as evidence.

Upstream: https://docs.mesa3d.org/drivers/zink.html and https://docs.mesa3d.org/relnotes/26.2.4.html. Source release tag `mesa-26.2.4`, tag object `3c479d6ab629eb9f6e2219fc77173058798e9795`, commit `96cb43121031992b85767f9c1be8f3f48e22b1d2`. Official source archive SHA256 `bce5f7fbebb934373b86c999a064d52fb5065878dc57f287f95346648ec832e9`. Mesa retains its upstream licenses; do not replace them with Hari's license. The tiny preload agent here is new GPL-3.0 code.

A project-scoped source build is configured for Windows x64/WGL, Zink only, native NVIDIA Vulkan loader, static MSVC runtime and a private shader cache. It does not install a driver, replace system libraries or change launcher/account settings. The agent preloads an explicit built Mesa library before GLFW opens its WGL context. The task launcher must scope `PATH`, `GALLIUM_DRIVER=zink` and cache variables to the isolated test child. The agent refuses a missing library or implicit backend choice.

Status: verified upstream source built successfully. A native WGL 4.6 core-context probe reported `Mesa`, `zink Vulkan 1.4(NVIDIA GeForce RTX 4090 (NVIDIA_PROPRIETARY))`, and Mesa 26.2.4. Required buffer-storage, indirect-draw, compute, SSBO, sync, texture-storage and program-introspection entry points were present. A clear/readback returned RGBA 64/127/191/255 with GL error 0. This checks hardware translation and readback, not game FPS. Full-pack parity/performance testing is ongoing. This is not a ready-to-install performance claim, and universal zero-overhead/no-hitch compatibility has not been established.

The WGL presentation candidate patch initializes all `kopper_loader_info` fields and forwards the effective current WGL swap interval to Zink's existing Kopper function before presentation. Upstream omitted both steps. The source diff is `patches/wgl-zink-swap-interval.patch`; `UPSTREAM.json` records its exact base and local DLL hashes. It retains the upstream license headers. No command marshalling experiment is included. A native 48-present test at intervals 0, 1, then 0 preserved readback and returned zero GL errors; elapsed values were approximately 11.3, 387.1, and 9.0 ms. These small-window probe times are diagnostic, not Minecraft FPS. Actual matched Minecraft performance remains the promotion gate.

Apply the patch only to a clean checkout at the pinned commit (`git apply --check`, then `git apply`). Build Windows x64 Release with MSVC, Meson and Ninja, `platforms=windows`, `gallium-drivers=zink`, no Mesa Vulkan drivers, `llvm=disabled`, `egl=disabled`, `glx=disabled`, and `b_vscrt=mt`. The installed `opengl32.dll`, `libgallium_wgl.dll`, and `z-1.dll` belong together in a private project folder. This is a development launcher bridge rather than a drop-in Forge mod: use the explicit preload agent and child-only environment, and confirm the actual GL renderer before accepting a run.
