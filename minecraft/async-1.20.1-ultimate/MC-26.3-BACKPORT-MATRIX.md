# HariMultiThread Ultimate — Minecraft 26.3 Backport Matrix

Target: Minecraft 1.20.1 / Forge 47.4.23 / Java 17

Design rule: backport result-preserving performance behavior into Hari's core, yield to an established provider when another performance mod owns the same subsystem, and keep world/render semantic rewrites out of the default profile.

## Core lanes

| Minecraft 26.3 change | Hari 1.20.1 status | Default | Compatibility contract |
|---|---|---:|---|
| Persistent mobs stop random walk/swim work when players are not nearby | Implemented and runtime-verified | ON | Minimal `Mob.checkDespawn` correction. Does not replace goals or change despawn eligibility. Real Forge QA observed a tagged persistent mob reaching `noActionTime=102`. |
| Faster repeated structure locating | Implemented safe subset | ON | Bounded cache for repeated structure-storage/NBT misses; vanilla `canCreateStructure` remains authoritative; invalidated on structure-data/reference mutation. Real Forge QA returned the same stronghold X/Z on repeated locate calls. |
| Non-creating region reads for structure locate (MC-311323 class of issue) | Implemented safe subset | ON | Missing `.mca` regions are existence-checked and cached without opening/creating a `RegionFile`; successful reads/writes keep vanilla format/logic, and a write invalidates the missing-region cache first. Release QA requires `/locate pillager_outpost` to create zero new region files. |
| Chunk-generation performance / density-cache redesign | Implemented experimental subset | **OFF** | `Cache2D.fillArray` can route through the existing X/Z cache while retaining 1.20.1 double precision. Real Forge ABBA did not meet the >=1% median-gain promotion rule, so this remains opt-in and automatically yields to HariChunk/C2ME. |
| Single-precision density evaluation | Experimental research only | OFF / not shipped | 26.3 changes intermediate rounding and can change terrain. Never enable in the forever-world/default profile without explicit parity acceptance. |
| Explicit interpolation-grid redesign | Experimental research only | OFF / not shipped | Data/worldgen semantic rewrite. Requires seed/terrain diff proof before any backport can be promoted. |

### Cache2D promotion evidence

Real Forge ABBA run `35273540019` used one identical JAR, Forge 47.4.23, Java 17, seed `8675309`, identical fresh chunk coordinates, and 14 baseline + 14 candidate samples. Candidate median generation time was about **0.42% slower** and candidate mean about **0.86% faster**. That failed the release rule requiring at least a 1% median gain with no mean regression, so the production default is OFF.

The first post-timing terrain hash used `Block.getId(BlockState)`. Because that numeric hash differed even between baseline A1 and baseline A2 at the same seed/coordinates, it is not treated as cross-JVM semantic-parity proof. The safety response is to preserve the previously validated 1.20.1 world-generation path by default.

## Client/render technology

| Minecraft 26.3 technology | Hari policy | Reason |
|---|---|---|
| Terrain MultiDrawIndirect | Provider-precedence lane | A correct 1.20.1 implementation requires shared terrain-buffer ownership, not a blind replacement of vanilla's per-section draw loop. Embeddium/Rubidium/Sodium-style renderers already own the terrain pipeline and win when present. Hari core remains renderer-neutral. |
| Order-independent transparency (OIT) | Not a performance default | Mojang documents a higher performance cost than the previous improved-transparency implementation. Treat as an optional visual feature, not an optimization. Oculus/Iris/other shader providers keep ownership. |
| ShaderC compilation on OpenGL | Provider/companion lane | Replacing 1.20.1's shader compilation contract touches core-shader/resource-pack compatibility and renderer bootstrap. It is not injected beside Oculus/Iris or other shader owners. |
| SDL3 window/input backend | External/launcher lane | Replacing GLFW is a client bootstrap/native-lifecycle migration, not an ordinary safe Forge performance mixin. It remains outside Hari core. |
| Uniform-block layout cleanup | Provider-owned client detail | 26.3 shuffles some shader uniform members to reduce memory. Hari does not rewrite client shader layouts underneath Embeddium/Oculus/resource packs. |

## Runtime technology

26.3's newer launcher/runtime configuration is not force-applied by Hari. Forge 1.20.1 remains pinned to Java 17 for the certified build; newer-JVM flags or GC behavior belong in a separately validated launcher profile rather than being changed from inside the running mod.

## Provider precedence

Hari's rule for this release is **one owner per invasive subsystem**:

- Entity scheduling/collision: Hari owns its established paths, with existing conservative third-party entity rules.
- Chunk scheduler: Hari yields the experimental density-cache mixin to HariChunk/C2ME.
- Region storage reads: Hari only short-circuits absent read/scan requests; vanilla writes and existing-region reads remain authoritative.
- Worldgen fast block placement/biome population: Noisium may coexist; Hari does not duplicate those targets.
- Terrain rendering: Embeddium/Rubidium/Sodium-family renderer owns it when present; Hari core remains renderer-neutral.
- Shader pipeline: Oculus/Iris-family provider owns it when present.

This matrix is an acceptance constraint, not merely documentation: a future 26.3 backport is promoted only if it either preserves Minecraft 1.20.1 results or is isolated behind an explicit experimental opt-in, and if an external performance provider is present Hari must not create a competing invasive owner.
