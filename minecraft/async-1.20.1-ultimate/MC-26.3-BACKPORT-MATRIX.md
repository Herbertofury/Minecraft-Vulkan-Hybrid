# HariMultiThread Ultimate — Minecraft 26.3 Backport Matrix

Target: Minecraft 1.20.1 / Forge 47.4.23 / Java 17

Design rule: backport result-preserving performance behavior into Hari's core, yield to an established provider when another performance mod owns the same subsystem, and keep world/render semantic rewrites out of the default profile.

## Core lanes

| Minecraft 26.3 change | Hari 1.20.1 status | Default | Compatibility contract |
|---|---|---:|---|
| Persistent mobs stop random walk/swim work when players are not nearby | Implemented | ON | Minimal `Mob.checkDespawn` tail correction. Does not replace goals or change despawn eligibility. |
| Faster structure locating | Implemented safe subset | ON | Bounded cache for repeated storage/NBT misses; vanilla `canCreateStructure` remains authoritative; invalidated on structure-data/reference mutation. |
| Chunk-generation performance / density-cache redesign | Implemented safe subset | ON | `Cache2D.fillArray` routes through the existing X/Z cache while retaining 1.20.1 double precision. Automatically yielded to HariChunk/C2ME. Additive with Noisium's 1.20.1 targets. |
| Single-precision density evaluation | Experimental research only | OFF / not shipped | 26.3 changes intermediate rounding and can change terrain. Never enable in the forever-world/default profile without explicit parity acceptance. |
| Explicit interpolation-grid redesign | Experimental research only | OFF / not shipped | Data/worldgen semantic rewrite. Requires seed/terrain diff proof before any backport can be promoted. |

## Client/render technology

| Minecraft 26.3 technology | Hari policy | Reason |
|---|---|---|
| Terrain MultiDrawIndirect | Provider-precedence lane | A correct 1.20.1 implementation requires shared terrain-buffer ownership, not a blind replacement of vanilla's per-section draw loop. Embeddium/Sodium-style renderers already own the terrain pipeline and must win when present. Do not inject a competing core renderer into Noxviola's established stack. |
| Order-independent transparency (OIT) | Not a performance default | Mojang explicitly documents a higher performance cost than the previous improved-transparency implementation. Treat as an optional visual feature, not an optimization. Oculus/Iris/other shader providers keep ownership. |
| ShaderC compilation on OpenGL | External/companion candidate | Replacing 1.20.1's shader compilation contract touches core-shader/resource-pack compatibility and the renderer bootstrap. It is not required for the server/entity/worldgen gains and is not injected into Hari core. |
| SDL3 window/input backend | External/launcher candidate | Replacing GLFW is a client bootstrap/native-lifecycle migration, not an ordinary safe Forge performance mixin. It remains outside Hari core. |

## Runtime technology

26.3's launcher/runtime configuration is not force-applied by Hari. Forge 1.20.1 is pinned to Java 17 for the certified build; flags or GC behavior that require a newer Java runtime must be delivered as a separate launcher profile and validated against Forge/mod compatibility rather than injected at runtime by the mod.

## Provider precedence

Hari's rule for this branch is **one owner per invasive subsystem**:

- Entity scheduling/collision: Hari owns its established paths, with existing conservative third-party entity rules.
- Chunk scheduler: Hari yields the density-cache mixin to HariChunk/C2ME.
- Worldgen fast block placement/biome population: Noisium may coexist; Hari does not duplicate those targets.
- Terrain rendering: Embeddium/Rubidium/Sodium-family renderer owns it when present; Hari core remains renderer-neutral.
- Shader pipeline: Oculus/Iris-family provider owns it when present.

This matrix is an acceptance constraint, not merely documentation: a future 26.3 backport is promoted only if it either preserves vanilla 1.20.1 results or is isolated behind an explicit experimental opt-in, and if an external performance provider is present Hari must not create a competing invasive owner.
